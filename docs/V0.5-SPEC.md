# v0.5 Spec: DiffViewer — Loop + Clipboard Steer

**Status:** Approved design, ready for implementation plan.
**Date:** 2026-05-29
**Supersedes for v0.5:** the broader `docs/PRD.md` "v1" scope. PRD remains the north-star vision (architecture panel, Neovim, multi-language). This spec narrows the *first shippable slice*.

---

## 1. Goal

Ship the thinnest **complete** review→redirect loop, browser-only:

> Claude Code edits files → hooks POST changes to a local server → browser renders per-turn grouped diff cards in real time → developer types a steer prompt → steer lands on the clipboard for paste-back.

This proves the core value (review a full turn's changes before continuing, redirect the agent) with no Neovim, no architecture panel, no multi-language parsing.

## 2. Scope

### In scope
- `PostToolUse` + `Stop` hooks (shell), registered globally.
- Hono server (ESM, Node 20+) exposing `POST /event`, `POST /turn-end`, `POST /steer`, `GET /stream`, `GET /`.
- In-memory modules: Event Normalizer (pure), TurnBuffer (per session), SSE Broadcaster.
- Browser UI: vanilla JS + `diff2html` (CDN), no build step.
- Clipboard steer (`pbcopy`).
- Idempotent `install.sh`.
- Vitest test suite.

### Out of scope (deferred to v1+)
Neovim Lua plugin · architecture panel (`GET /arch`, forward/reverse imports, import chain, `heuristics.json`, `.diffviewer.json`) · per-language parsers · `layer` field · tmux injection · Bash command capture · turn-history persistence · function-level call graphs · runtime trace · configurable port (hardcode `3333`) · Windows/Linux (`pbcopy`/macOS assumed).

## 3. Diff model — per-file (decided)

One diff card **per file**, uniform across Write / Edit / MultiEdit. `oldString` is **not** used (it is a fragment, not a whole file, and cannot produce a file-level unified diff).

| Side | Source |
|---|---|
| Old content | `git show HEAD:<path>` — any non-zero exit (new file, untracked, non-git dir, detached HEAD) ⇒ treat as empty string |
| New content | current file read from disk (`cat <path>`) at hook time |
| Diff | `diff.createPatch(path, oldContent, newContent)` (server-side) |
| `isNew` | true when old content is empty |

**Consequence:** two edits to the same file within one turn produce **one** cumulative diff (matches what `git diff` would show). The TurnBuffer **dedupes by path, keeping the latest event** — the most recent disk read already contains all prior edits to that file.

## 4. Data shapes

```js
// NormalizedEvent — dropped from v1: layer, seq, ts (no consumer in v0.5)
{
  tool: 'write' | 'edit',   // tool that last touched the file (drives the badge)
  path: string,
  unifiedDiff: string,      // diff.createPatch() output, ready for diff2html
  isNew: boolean            // old content was empty
}

// TurnSnapshot
{
  sessionId: string,
  turnNumber: number,       // per-session counter; drives browser tab title
  events: NormalizedEvent[],// ordered by first-touch, deduped by path
  startedAt: number,        // epoch ms of first event in turn
  completedAt: number       // epoch ms at flush
}
```

**Forward-compat:** the browser destructures only the fields it uses (`tool`, `path`, `unifiedDiff`, `isNew`). When v1 re-adds `layer`, the change is additive — v0.5 code must never guard on `event.layer === undefined`.

## 5. Components & data flow

```
Claude Code
  PostToolUse (Write|Edit|MultiEdit) → curl POST :3333/event   { sessionId, tool, path, oldContent, newContent }
  Stop                               → curl POST :3333/turn-end { sessionId }

server.js (Hono, ESM, Node 20+, daemon on :3333)
  POST /event     → Normalizer → TurnBuffer.add (dedupe by path)
  POST /turn-end  → flush session buffer → skip if empty → Broadcaster.emit → delete session entry
  POST /steer     → echo text | pbcopy   (400 if empty/whitespace)
  GET  /stream    → SSE: `event: turn-complete\ndata: <TurnSnapshot json>\n\n`
  GET  /          → serve browser/index.html

browser/ (diff2html + vanilla JS, no build)
  EventSource /stream → per-session turn cards → collapsible per-file diffs → steer box → POST /steer
  tab title: `(N) Diff Viewer`
```

### Module responsibilities
| Module | File | Responsibility | Depends on |
|---|---|---|---|
| Event Normalizer | `src/normalizer.js` | pure: raw event → `NormalizedEvent` via `createPatch` | `diff` |
| TurnBuffer | `src/turnBuffer.js` | per-session accumulator (`add`/`flush`/`reset`), dedupe by path, `Map<sessionId,TurnBuffer>` registry | — |
| SSE Broadcaster | `src/broadcaster.js` | `subscribe`/`unsubscribe`/`emit`; eager cleanup on `res 'close'` + on emit failure | — |
| Event Receiver | `src/eventReceiver.js` | `/event` + `/turn-end` handlers; wires Normalizer + TurnBuffer + Broadcaster | the three above |
| Steer Handler | `src/steerHandler.js` | `/steer` → injectable exec → `pbcopy`; validates non-empty | — |
| Static + entry | `server.js` | mount routes, `GET /stream`, serve `browser/`, export app for tests | all |

## 6. Hooks (fail-silent contract)

Both hooks: `curl -sf --max-time 1`, **exit 0 always** (server down or any error must never break a Claude session).

- `hooks/post-tool-use.sh` — reads `$CLAUDE_TOOL_NAME`, `$CLAUDE_TOOL_INPUT_JSON`, `$CLAUDE_SESSION_ID`. For Write/Edit/MultiEdit: derive `path`(s); `oldContent = git show HEAD:<path> 2>/dev/null || echo ""`; `newContent = cat <path>`; POST to `/event`. Unknown tool ⇒ exit 0, no POST.
- `hooks/stop.sh` — POST `{ sessionId }` to `/turn-end`; exit 0 always.

## 7. Install script

`scripts/install.sh` — idempotently patches `~/.claude/settings.json`:
- Appends a **new sibling** `PostToolUse` entry (matcher `Write|Edit|MultiEdit`) and a **new sibling** `Stop` entry (no matcher). Same-matcher entries are evaluated independently by Claude Code, so this never touches the existing lint/judge/autofix blocks — keeping the install hermetic and a future uninstall a clean find-and-remove.
- Hook `command` uses **`~/`-relative** form (`~/.claude/tools/diff-viewer/hooks/...`), matching existing entries and surviving cross-machine bootstrap (PRD US-9). No `$HOME` resolution needed.
- Merge via inline `node -e` (Node 20 already required) — no `jq` dependency.
- Idempotency: scan all entries' `hooks[].command` for the diff-viewer command substring; skip if already present. No duplicates on re-run.
- Scaffold a minimal valid `settings.json` if absent.
- Exit 0 even when entries already present.

## 8. Acceptance criteria

### Normalizer (`src/normalizer.js`)
- N1 — existing file: `isNew:false`, `unifiedDiff` has `@@` hunks reflecting the change.
- N2 — new file (empty old): `isNew:true`, diff all-green (`+` only).
- N3 — `tool` carries the triggering tool name (`'write'`/`'edit'`).
- N4 — diff produced by `createPatch`; header contains the filename.

### TurnBuffer (`src/turnBuffer.js`)
- TB1 — `add` then `flush` returns events in first-touch order.
- TB2 — empty `flush` ⇒ `events: []`.
- TB3 — `reset` clears; subsequent `add`/`flush` returns only post-reset events.
- TB4 — **dedupe by path**: two events for the same path ⇒ one event (the latest) in the snapshot.
- TB5 — `turnNumber` increments per successive `flush` on a session.
- TB6 — session isolation: `s1` events never appear in `s2` flush.
- TB7 — `startedAt` = first add time; `completedAt` = flush time.

### Broadcaster (`src/broadcaster.js`)
- B1 — `subscribe` registers a client.
- B2 — `emit` writes `event: turn-complete\ndata: <json>\n\n` to each client.
- B3 — multiple subscribers all receive the payload.
- B4 — dead client (write throws / `res` closed) removed; not written to again.
- B5 — `unsubscribe` stops further writes.

### Server routes
- E1 — `POST /event` (Write payload) ⇒ normalized + buffered, 200.
- E2 — unknown tool ⇒ 200, nothing buffered.
- E3 — `POST /turn-end` ⇒ Broadcaster receives a `TurnSnapshot` with buffered events.
- E4 — empty turn ⇒ no emit, 200.
- E5 — session isolation across `/event`/`/turn-end`.
- E6 — after `/turn-end`, session entry deleted; new `/event` recreates it.

### Steer (`src/steerHandler.js`)
- ST1 — valid text ⇒ exec invoked with text on stdin, 200.
- ST2 — empty text ⇒ 400, exec not invoked.
- ST3 — missing `text` ⇒ 400.
- ST4 — whitespace-only ⇒ 400.

### Browser (`browser/app.js`)
- UI1 — `turn-complete` SSE ⇒ new turn card with one diff card per event.
- UI2 — Write vs Edit badge visually distinct.
- UI3 — `isNew` ⇒ "new file" indicator; diff all-green.
- UI4 — per-file diff collapsed by default; header toggles.
- UI5 — Send ⇒ `POST /steer { sessionId, text }`; clears input on success.
- UI6 — `document.title` = `(N) Diff Viewer` (N = turn-card count).
- UI7 — cards from different sessions grouped/labeled separately.
- UI8 — disconnect ⇒ native EventSource reconnect; visible disconnected indicator.

### Hooks (manual / bash test)
- H1 — Write/Edit/MultiEdit ⇒ correct POST body to `/event`.
- H2 — `git show` failure (new/untracked/non-git) ⇒ empty old content, still POSTs.
- H3 — server down ⇒ exit 0 within ~1s.
- H4 — unknown tool ⇒ exit 0, no POST.
- S1 — `stop.sh` POSTs `{sessionId}` to `/turn-end`; exit 0 always.

### Install (`scripts/install.sh`)
- I1 — adds both entries as **new siblings** without modifying or removing existing hook entries (lint/judge/autofix untouched).
- I2 — idempotent: second run detects the diff-viewer command substring and makes no change (no duplicates).
- I3 — scaffolds file when absent.
- I4 — hook `command` uses `~/`-relative form matching existing entries.
- I5 — PostToolUse matcher = `Write|Edit|MultiEdit`; Stop entry has no matcher.
- I6 — exit 0 when entries already present.

## 10. Risks & mitigations (v0.5)
- **git show in non-git/new-file** → hook falls back to empty old content (per-file model handles this natively).
- **Session leak on crash** → `/turn-end` deletes the session entry; a session that never fires Stop leaks one buffer (acceptable at personal scale; document it).
- **SSE reconnect gap** → turns during disconnect are lost (no persistence by design); browser shows a disconnected indicator so the user knows.
- **diff2html input format** → `createPatch` emits `--- a/<f>` / `+++ b/<f>`; confirm diff2html `inputFormat:'diff'` extracts the filename for syntax highlighting.
- **settings.json hook schema** → verified against the live install (2026-05-29): `PostToolUse` entries are `{matcher, hooks:[{type:"command",command}]}`; `Stop` entries omit `matcher`. Existing entries occupy matcher `Write|Edit|MultiEdit` (lint/judge) and `Stop` (autofix); v0.5 adds new siblings (see §7).
- **MultiEdit tool JSON schema** → confirm field names from a real session; per-file model only needs `path`(s), reducing exposure to schema drift.
- **Stop-hook autofix ordering (known gap)** → the existing `Stop` hook `lint-autofix.sh` mutates files *after* PostToolUse captured the diffs, so the browser shows **pre-autofix** content. v0.5 does not capture autofix changes (they are not Write/Edit tool calls). Accepted for v0.5; candidate for a later "post-Stop re-diff" pass.

## 11. Resolved decisions (was: open questions)
1. **Steer box cardinality → per-card.** Each turn-card carries its `sessionId`; the steer POST uses that card's session, so it is unambiguous by construction (no global session picker, no silent wrong-terminal steer). Aligns with the per-session card grouping (UI7).
2. **settings.json hook schema → verified** against the live install (see §10). `install.sh` adds **new sibling** entries with `~/`-relative command paths; idempotency via command-substring scan (see §7, AC-I1–I6).
