# V0.6 — Sidecar Ingestion Spec (Commandr Phase 2 re-homing)

**Status:** Adopted 2026-06-09. Implements Commandr UNIFICATION-BLUEPRINT Phase 2 (decision 5: DiffViewer
reads the filesystem, not Claude Code hooks) under decision 4 (diff content is loop-internal: projected
to a harness-local sidecar, never stored on the `.agents/` bus).

## Decision summary

- **Sidecar home:** repo-local `<repo>/.diffviewer/turns/<sessionId>/` in the repo being edited. Gitignored.
- **Ingestion:** the DiffViewer server watches sidecar directories natively (`fs.watch`); the legacy
  `POST /event` + `POST /turn-end` path is retained for tests and as a fallback transport.
- **Snapshot payload:** raw `oldContent`/`newContent` strings per file event. The server computes
  `unifiedDiff` and `isNew` with the existing normalizer — adapters stay dumb writers.
- **Steer:** v0.6 adopted clipboard via `POST /steer`; current main also supports direct OpenCode steering when `OPENCODE_SERVER_URL` is configured.

## 1. Snapshot file contract (v1)

Path: `<repo>/.diffviewer/turns/<sessionId>/turn-<N>.json`

- `<sessionId>`: harness session ID, sanitized to `[A-Za-z0-9._-]` (any other byte → `_`). Max 128 chars.
- `<N>`: positive integer, monotonically increasing per session. Writer derives N as
  `max(existing turn-*.json) + 1` (single writer per session directory).

Schema:

```json
{
  "version": 1,
  "sessionId": "string — same as directory name, pre-sanitization value not preserved",
  "harness": "claude-code | opencode",
  "task": "string | null — bus task id if the session is working a claimed task, else null",
  "turnNumber": 1,
  "startedAt": 1760000000000,
  "completedAt": 1760000001000,
  "events": [
    { "tool": "Write | Edit | MultiEdit", "path": "string", "oldContent": "string", "newContent": "string" }
  ]
}
```

- `tool` uses the harness-reported name; the server's normalizer maps it (`Write` → `write`, others → `edit`)
  exactly as it does for `POST /event`.
- `oldContent` is captured at tool time: content of the file immediately *before* the write
  (CC: `git show HEAD:<path>`, empty if untracked; OC: pre-write disk read in `tool.execute.before`).
  `newContent` is the post-write disk content. Empty string when unreadable.
- `events` preserves tool-invocation order. Writers MAY dedupe by path (keep latest); the server's
  TurnBuffer dedupes regardless, so duplicates are tolerated.
- Timestamps are ms epoch integers. `startedAt` = first captured event; `completedAt` = snapshot write time.

## 2. Write protocol (atomicity)

1. Writer assembles the full JSON in memory or a staging file.
2. Writer writes to `<sessionDir>/.tmp-turn-<N>.json`, then `rename(2)` to `turn-<N>.json`.
3. Watchers MUST ignore any file whose basename does not match `^turn-\d+\.json$` (dotfiles, tmp, partial names).

Rename on the same filesystem is atomic — a watcher never observes partial JSON under this protocol.
If parsing still fails (foreign writer), the server logs and skips the file; it does not crash the watcher.

## 3. Per-turn accumulation (adapter side)

- **Claude Code** (`hooks/post-tool-use.sh`, `hooks/stop.sh`):
  - PostToolUse appends one JSON line per file event to `<sessionDir>/.pending.jsonl` (POSIX append, atomic per line).
  - Stop hook: if `.pending.jsonl` exists and is non-empty, wrap lines into the snapshot envelope
    (`jq -s`), write tmp, rename, delete `.pending.jsonl`. Empty/no pending → no snapshot (empty turns
    are not projected). Fail-silent, `exit 0` always, 1s budget per hook (matches v0.5 hook discipline).
- **OpenCode** (`adapters/opencode/diffviewer.js` plugin):
  - `tool.execute.before` for write/edit/apply_patch tools: capture `{path, oldContent}` from disk into an in-memory
    per-`sessionID` pending list. `tool.execute.after`: read `newContent` from disk, complete the event.
  - `apply_patch` payloads are parsed from `*** Add/Update/Delete File:` sections. Delete+add overwrites of the same path are de-duplicated into one event.
  - `session.status` (idle) — same trigger and in-flight guard pattern as Commandr's `checkpoint.js`:
    flush pending list to a snapshot file. Empty pending → no file.

## 4. Server watcher

- Watch roots: CLI args (`node server.js /path/to/repo …`) or `DIFFVIEWER_WATCH_ROOTS`
  (colon-separated). Each root watches `<root>/.diffviewer/turns/` recursively (created lazily if absent).
- On a new `turn-<N>.json`: parse → for each event run the existing normalizer → feed the existing
  per-session TurnBuffer keyed by `sessionId` → flush → broadcast the same `turn-complete` SSE
  TurnSnapshot the POST path produces. One snapshot file == one turn == one SSE frame.
- After a successful broadcast the server unlinks the consumed snapshot file (the sidecar is a queue,
  not an archive). Files written while the server is down are ingested on startup scan (ordered by N), so
  no turn is lost across restarts.
- Parse/IO errors: log to stderr, leave the file in place, continue watching.

## 5. Hygiene

- Repos consuming DiffViewer add `.diffviewer/` to gitignore; `scripts/install.sh` appends it to the
  user's global git excludes file (idempotent).
- Adapters prune session directories with no activity for >7 days at session start (best-effort).

## 6. Out of scope (v0.6)

- Cross-harness steer routing. Current direct steering is OpenCode-only and requires `OPENCODE_SERVER_URL` plus a real OpenCode session id.
- Writing anything under `.agents/` — bus events remain Commandr adapters' job (SPEC v0.1).
- Multi-repo discovery/registry; roots are explicit.
- Tauri shell (decision 5 "later").
