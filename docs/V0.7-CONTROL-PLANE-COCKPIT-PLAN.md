# V0.7 Plan: Control-Plane Cockpit

**Status:** Design / implementation backlog. Runner integration is *aspirational* — `commandr-omp-runner` Level 1 is a thin omp subprocess wrapper today (no bus writes, no approvals, no tests); bus-integrated progress/approval/artifact events require Level 2 (omp RPC mode + SPEC additions for `approval_requested`/`artifact_created`). Action-registry, review-package, and LSP-evidence slices are buildable now against existing bus tools + sidecars. **Non-normative:** `approval_requested`, `artifact_created`, `.agents/approvals/<task>.pending`, `.denied`, and `workspaces/` are NOT in SPEC v0.3; do not consume them until added via a conformance-backed SPEC change.
**Date:** 2026-06-19 (must-fix revision: corrected false "Level 1 complete" premise, fenced SPEC-forbidden events, split Slice 4, bifurcated the approval vocabulary from the live mobile commit-gate).
**Purpose:** Carry forward the Agent-Native + Builder Skills + omp synthesis into DiffViewer so future agents build the next UI in the right direction.

---

## Product Shape

DiffViewer is the L5 UI over the Commandr L3 bus. The next target is not just a diff page; it is a local-first AI operations cockpit for supervising tasks, runners, approvals, evidence, logs, and review packages.

Current browser/server remains useful as the tracer bullet. Tauri is the later shell once the action vocabulary and data model harden.

Current tracer bullets already in main:

- Sidecar ingestion from OpenCode and Claude-compatible adapters.
- Direct OpenCode steering through `OPENCODE_SERVER_URL` and `/session/:id/prompt_async`.
- Mobile approval projection that writes Commandr approval tokens (PR #2 — the live, **blocking** commit-gate approval path).
- Architecture tab from CodeBoarding `analysis.json` artifacts (PR #7).
- Annotation loop: per-card inline notes → `UserPromptSubmit` injection (PR #4).

---

## Boundary

DiffViewer owns:

- human-facing task board projections
- diff cards and sidecar ingestion
- approval UI
- evidence pinning UI
- review package UI
- runner log display
- LSP diagnostics/symbol evidence display
- Neovim bridge: file/line navigation, selection context, debug evidence handoff
- local SQLite/index cache for fast browsing
- Tauri/native notifications when that phase starts

DiffViewer must not own:

- authoritative task lifecycle
- approval token semantics
- claim/complete rules
- Commandr SPEC event definitions
- runner-private state

Authoritative lifecycle remains in Commandr `.agents/`. DiffViewer can cache and render it, but must be able to rebuild from bus files plus sidecar/artifact files.

## Agent-Native Action Registry

Borrow the Agent-Native idea that UI and agent share actions. Implement it locally: every meaningful cockpit operation should be a named action that a human click or an agent request can invoke through the same validation path.

Initial action registry (status annotated: **live** = mapped to a merged backend today; **speculative** = no backend yet, correctly fenced as runner/future-owned):

| Area | Actions | Handler target | Status |
|---|---|---|---|
| Tasks | `task.create` | orchestrator/spawn-agents (no `bin/create`) | speculative |
| Tasks | `task.claim`, `task.progress`, `task.complete`, `task.fail` | `bin/claim`, `bin/progress`, `bin/complete` (SPEC §4-6) | **live** |
| Sessions | `session.start`, `session.cancel` | runner adapter | speculative |
| Approvals (commit-gate) | `approval.approve`, `approval.deny` | mobile `writeApprovalToken` / `handleReject` → `.agents/approvals/<task>.approved` (SPEC §7, PR #2) | **live** |
| Approvals (runner action) | `approval.request` | runner policy → neutral progress + artifact ref (NOT a bus event; NOT a second gate) | future (Level 2) |
| Artifacts | `artifact.create` | local `.diffviewer/artifacts/`; runner workspace | local OK; bus event future |
| Artifacts | `evidence.pin`, `review.generate` | DiffViewer-local + `bin/council` (SPEC §12) | **live** (council) / local |
| Runners | `runner.start`, `runner.stop`, `runner.install` | runner adapter | speculative |
| Machines | `machine.connect` | future SSH/native | speculative |

**Approval vocabulary bifurcation (must-fix):** there are two distinct "approval" concepts that must not be conflated:
- **Commit-gate approval (live, blocking):** the mobile path writes `.agents/approvals/<task>.approved`, read by `bin/pre-commit-gate` at commit time (SPEC §7, C11). `approval.approve`/`approval.deny` map to the **existing** mobile handlers, NOT a future runner host tool.
- **Runner action approval (future, non-blocking):** a runner detects a risky action and projects it as neutral progress + a workspace artifact ref for human review in DiffViewer. It does NOT block mid-turn, does NOT emit `approval_requested`, does NOT create `.pending`. The commit gate remains the single enforceable block.

Each action should define:

| Field | Purpose |
|---|---|
| `name` | Stable action id. |
| `schema` | Zod or JSON-schema input contract. |
| `actor` | `human`, `agent`, or `system`. |
| `risk` | `low`, `medium`, or `high`. |
| `requiresApproval` | Human gate requirement before side effect. |
| `handler` | Tauri command, server handler, or Commandr subprocess. |
| `auditEvent` | Local audit row and optional Commandr event. |

Do not send arbitrary agent text directly into side effects. Agent requests should become action proposals, then pass schema validation and risk/approval policy.

## Builder-Style Skills for Review Packages

Builder Skills suggest a useful packaging model for workflows. DiffViewer should produce inspectable artifacts, not just chat summaries.

Candidate local skills/workflows:

| Workflow | Output |
|---|---|
| `visual-plan` | Diagram + task/file map before implementation. |
| `visual-recap` | What changed, screenshots, diffs, tests, risks. |
| `review-package` | Diff bundle, Commandr events, council verdict, pinned evidence, residual risks. |
| `evidence-package` | Security/QA-ready evidence set with timestamps and source paths. |
| `runner-report` | Runner stdout/stderr summary, status, artifacts, failures. |

Store generated artifacts under a DiffViewer-owned ignored directory first, for example `.diffviewer/artifacts/<task>/`. Runner workspace artifacts live at a **runner-defined** path (e.g. `workspaces/TASK-XXX/artifacts/` per `llm-wiki/commandr-omp-runner/HOST-TOOLS.md`); DiffViewer resolves the path from the event/artifact reference and never asserts it. `workspaces/` is a runner convention, not a SPEC §2 bus contract.

**Artifact consumption from runners (revised 2026-06-19):**
- ~~Level 1: Infer artifacts from `write`/`edit`/`bash` tool calls in NDJSON stream~~ — **dropped.** Inferring couples DiffViewer to omp's private NDJSON stream and duplicates a runner responsibility. (Persisting to `.diffviewer/artifacts/` is bus-safe — `.diffviewer/` is DiffViewer-local and gitignored — but the inference itself is the runner's job.)
- Level 2 (future): consume explicit artifact references from runner-neutral progress lines (the runner writes the full artifact to its workspace and emits a neutral `task_progress` note + path reference). DiffViewer renders the reference. No `artifact_created` bus event is consumed until SPEC §6 defines it with a conformance case.

Only promote a bus event when Commandr has a concrete SPEC event and conformance case for artifact references.

## omp Runner Visibility

omp is an L2 worker, not the UI or bus. DiffViewer should make omp runs observable through Commandr and sidecars.

Expected future flow (aspirational — blocked on the runner being bus-integrated):

```
Commandr task packet
  -> commandr-omp-runner claims task (bin/claim)            [NOT yet implemented]
  -> omp executes in worktree/session
  -> runner emits neutral Commandr progress (bin/progress)  [NOT yet implemented]
  -> runner writes artifacts to workspace + references them in neutral progress
  -> DiffViewer watches bus events + sidecar snapshots
  -> cockpit renders logs, diffs, artifacts
```

**Level 1 (current — scaffold, not complete):** `commandr-omp-runner` uses `--mode json` and tees raw NDJSON to a runner-local `--progress` file + stderr. It does NOT write `.agents/events.jsonl`. So DiffViewer watching `events.jsonl` for runner-originated `task_progress`/`task_complete`/`task_failed` would see **nothing** today. The runner does not claim, does not set `AGENTS_TASK_ID`, does not move packets to `done/`, performs no approval/policy logic, and has no tests. See `llm-wiki/commandr-omp-runner/README.md` for the honest status.

**Level 2 (future, blocked on `omp --mode rpc`):** RPC host tools. DiffViewer can:
- Render explicit artifact references carried in neutral `task_progress` lines (the runner emits the ref; the artifact body lives in the workspace).
- Show a policy-violation log from neutral progress lines (e.g. `"policy: destructive bash blocked (high risk); see workspaces/.../policy-0001.json"`).
- Link to workspace artifacts at the runner-defined path.
- RPC mode enables real-time streaming + bidirectional steer. It does **NOT** add a second blocking approval gate — the commit `pre-commit-gate` (SPEC §7) stays the single enforceable block.

UI requirements for omp visibility:

- Runner badge: `claude-code`, `opencode`, `omp`, `shell`, etc.
- Live log panel per runner session.
- Diff cards remain source-agnostic through `.diffviewer/turns/` snapshots.
- ~~Approval requests render as action proposals with risk level~~ → **Runner policy violations render as neutral progress entries + artifact links for post-hoc review.** The enforceable approval UI is the **commit-gate** (mobile, live), not a mid-turn runner gate.
- Artifact cards link to review/evidence packages.
- Failure state separates runner crash from task completed with failing acceptance criteria.

## LSP Evidence Panel

Language servers should be a baseline evidence source for code-changing tasks. DiffViewer should not start every LSP globally. It should display LSP output when a runner or project profile exposes it.

Policy:

- LSP lifecycle belongs to L1/L2 runner adapters, not DiffViewer's UI state.
- DiffViewer/Tauri may start project-scoped LSPs later, but only through an explicit runner/session action.
- Cache summaries locally if useful; do not write raw LSP state to Commandr `.agents/`.
- Pair LSP diagnostics with typecheck/test status; do not treat clean diagnostics as task success.

UI targets:

| UI element | Evidence |
|---|---|
| Diagnostics badge | clean / dirty / unavailable per runner session |
| Diff card symbol panel | exported symbols changed, definitions, references/callers |
| Review package | diagnostics summary before approval |
| Risk scoring | higher risk when exported symbol changed and references exist |

This makes the cockpit feel IDE-aware without making DiffViewer the owner of language-server lifecycle.

## Neovim Operator Bridge

For operators using Neovim as an IDE replacement, DiffViewer should interoperate instead of trying to replace it.

**Existing artifact:** `DiffViewer/nvim/diffviewer.lua` (currently untracked in-repo) is a v0 Neovim bridge that consumes the same `/stream` SSE as the browser, renders turns in a diff buffer, declines files via `git checkout --`, and steers the agent via `POST /steer`.

**Contract (declared, not invented):** the cockpit (browser/Tauri) and the Neovim bridge are two L5 lanes that consume the **same** `/stream` SSE and operate on the **same** `TurnSnapshot` shape (`docs/ARCHITECTURE.md`). The cockpit is the rich view (review packages, approvals, evidence, architecture); the Neovim bridge is the lightweight statusline + steer + decline lane. No new bridge protocol — the SSE stream + `TurnSnapshot` is the shared contract. The bridge should gain a `task_annotation` write path (via `bin/annotate-write` or `POST /annotate`) so the operator can drop card-anchored notes from Neovim.

Ideas (beyond the v0 bridge):

- Deep link from a diff card or review package to `nvim <file> +<line>` or an operator-configured command.
- Accept a selection payload from Neovim and turn it into a `task_annotation` or steer proposal.
- Watch Neovim/Mason diagnostics summaries as evidence, not lifecycle state.
- Import DAP reproduction notes or stack traces as review/evidence artifacts.
- Refresh DiffViewer review state when diffview/Neovim sees external agent edits.

Boundary: Neovim remains the human IDE lane (Mason/lspconfig/nvim-dap owned by the operator, never bus state). DiffViewer owns review packages, approvals, evidence browsing, and bus projection.

## Suggested Implementation Slices

### Slice 0: Stabilize Current Browser Cockpit — **buildable now**

Keep this slice small and do it before Tauri work.

Acceptance criteria:

- Recent turn history can replay after browser refresh, not only over live SSE.
- Demo cards are explicitly marked as synthetic and cannot imply direct steering.
- OpenCode direct steering displays success/failure state from `/steer`.
- Sidecar session ids are preserved well enough to target real OpenCode sessions.

### Slice 1: Action Registry Design Doc — **buildable now (doc only)**

Create `docs/COCKPIT-ACTIONS.md` with the action table, schemas, risk levels, and mapping to existing Commandr commands/events. Mark runner/approval-request/artifact-bus actions as **future**, not current.

Acceptance criteria:

- All actions list owner: DiffViewer-local, Commandr command, or future runner adapter.
- High-risk actions require approval.
- No action bypasses Commandr for lifecycle state.
- `approval.approve`/`approval.deny` map to the **existing** mobile commit-gate handlers, not a future runner host tool.

### Slice 2: Local Action Dispatcher — **buildable now (for mapped actions)**

Implement a small in-process dispatcher around existing handlers. Runner/approval-request/artifact-bus actions are stubs.

Acceptance criteria:

- Browser/Tauri calls and agent proposals use the same dispatcher.
- Invalid schema returns a structured error.
- Risk level is visible to UI before execution.

### Slice 3: Review Package Artifact — **buildable now (highest value, lowest blocker)**

Generate a task-level review package from existing data: TurnSnapshots, bus events (`task_claimed`, `task_progress`, `task_complete`, `task_failed`, `council_verdict`, `task_annotation` — all live SPEC §6 events), approval state, council verdict, and git diff summary.

Acceptance criteria:

- Output is a stable JSON or Markdown artifact under `.diffviewer/artifacts/<task>/`.
- It can be regenerated without mutating bus state.
- UI can render it as a card.

### Slice 4: Runner Panel — **split required**

Split into two sub-slices:

**Slice 4a: Sidecar session panel — buildable now.** Render Claude/OpenCode sidecar sessions (already work). Distinguish running, completed, failed.

**Slice 4b: omp-runner panel — blocked.** Blocked on (i) `commandr-omp-runner` being genuinely bus-integrated (claim, `AGENTS_TASK_ID`, `bin/progress`/`bin/complete`, `done/` move — none implemented today), (ii) `omp --mode rpc` adoption, (iii) SPEC additions for any new event types. Until then, the omp-runner panel can at most tail the runner's runner-local `--progress` file (a stopgap that couples DiffViewer to omp internals — acceptable for debugging, not as a product slice).

Acceptance criteria (4a):

- Supports current Claude/OpenCode sidecars.
- Distinguishes running, completed, failed.
- Does NOT claim "waiting-for-approval" for runner-originated events (there is no mid-turn runner gate; the enforceable gate is commit-time).

Acceptance criteria (4b) — blocked, do not start until the runner meets Level 1:

- `commandr-omp-runner` calls `bin/claim`/`bin/progress`/`bin/complete` and writes real bus events.
- Panel renders neutral progress + artifact references from `events.jsonl`.
- Policy violations render from neutral progress lines, not a `approval_requested` event.

### Slice 4.5: LSP Evidence Panel — **buildable now against existing sidecar harnesses; omp LSP path blocked**

Add an evidence panel fed by runner-provided LSP summaries or project-scoped LSP adapters.

Acceptance criteria:

- UI can show diagnostics clean/dirty/unavailable for a task.
- Changed exported symbols can show definition/reference context when available.
- Missing LSP does not block review; it shows `unavailable`.
- LSP state is cached locally or in artifacts, not written as Commandr lifecycle state.

### Slice 5: Tauri Shell — **buildable after 0-3**

Move the cockpit to Tauri only after action registry and artifacts stabilize.

Acceptance criteria:

- Existing browser UI remains usable during migration.
- SQLite/cache is derived, not authoritative.
- Native notifications are driven by bus/action state.

## Non-Goals

- Replacing Commandr `.agents/` with a DiffViewer database.
- Creating another task queue.
- Storing runner-private transcripts on the bus.
- Letting visual artifacts become the source of truth.
- Building Tauri before the action registry is understood.
- Building a second blocking approval gate alongside the live mobile commit-gate (the runner projects risk as neutral progress; the commit `pre-commit-gate` is the single enforceable block).
