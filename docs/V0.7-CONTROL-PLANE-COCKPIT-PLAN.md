# V0.7 Plan: Control-Plane Cockpit

**Status:** Future refactor / implementation backlog. Aligned with `llm-wiki/commandr-omp-runner/HOST-TOOLS.md` schema.
**Date:** 2026-06-19.
**Purpose:** Carry forward the Agent-Native + Builder Skills + omp synthesis into DiffViewer so future agents build the next UI in the right direction.

---

## Product Shape

DiffViewer is the L5 UI over the Commandr L3 bus. The next target is not just a diff page; it is a local-first AI operations cockpit for supervising tasks, runners, approvals, evidence, logs, and review packages.

Current browser/server remains useful as the tracer bullet. Tauri is the later shell once the action vocabulary and data model harden.

Current tracer bullets already in main:

- Sidecar ingestion from OpenCode and Claude-compatible adapters.
- Direct OpenCode steering through `OPENCODE_SERVER_URL` and `/session/:id/prompt_async`.
- Mobile approval projection that writes Commandr approval tokens.
- Architecture tab from CodeBoarding `analysis.json` artifacts.

---

## Boundary

DiffViewer owns:

- human-facing task board projections
- diff cards and sidecar ingestion
- approval UI
- evidence pinning UI
- review package UI
- runner log display
- LSP diagnostics/symbol evidence display
- Neovim bridge: file/line navigation, selection context, debug evidence handoff
- local SQLite/index cache for fast browsing
- Tauri/native notifications when that phase starts

DiffViewer must not own:

- authoritative task lifecycle
- approval token semantics
- claim/complete rules
- Commandr SPEC event definitions
- runner-private state

Authoritative lifecycle remains in Commandr `.agents/`. DiffViewer can cache and render it, but must be able to rebuild from bus files plus sidecar/artifact files.

## Agent-Native Action Registry

Borrow the Agent-Native idea that UI and agent share actions. Implement it locally: every meaningful cockpit operation should be a named action that a human click or an agent request can invoke through the same validation path.

Initial action registry:

| Area | Actions | Handler target |
|---|---|---|
| Tasks | `task.create`, `task.claim`, `task.progress`, `task.complete`, `task.fail` | Commandr command or bus writer |
| Sessions | `session.start`, `session.cancel` | runner adapter |
| Approvals | `approval.request`, `approval.approve`, `approval.deny` | Commandr approval path |
| Artifacts | `artifact.create`, `evidence.pin`, `review.generate` | DiffViewer artifact store + runner workspace |
| Runners | `runner.start`, `runner.stop`, `runner.install` | runner adapter |
| Machines | `machine.connect` | future SSH/native layer |

Each action should define:

| Field | Purpose |
|---|---|
| `name` | Stable action id. |
| `schema` | Zod or JSON-schema input contract. |
| `actor` | `human`, `agent`, or `system`. |
| `risk` | `low`, `medium`, or `high`. |
| `requiresApproval` | Human gate requirement before side effect. |
| `handler` | Tauri command, server handler, or Commandr subprocess. |
| `auditEvent` | Local audit row and optional Commandr event. |

Do not send arbitrary agent text directly into side effects. Agent requests should become action proposals, then pass schema validation and risk/approval policy.

## Builder-Style Skills for Review Packages

Builder Skills suggest a useful packaging model for workflows. DiffViewer should produce inspectable artifacts, not just chat summaries.

Candidate local skills/workflows:

| Workflow | Output |
|---|---|
| `visual-plan` | Diagram + task/file map before implementation. |
| `visual-recap` | What changed, screenshots, diffs, tests, risks. |
| `review-package` | Diff bundle, Commandr events, council verdict, pinned evidence, residual risks. |
| `evidence-package` | Security/QA-ready evidence set with timestamps and source paths. |
| `runner-report` | Runner stdout/stderr summary, status, artifacts, failures. |

Store generated artifacts under a DiffViewer-owned ignored directory first, for example `.diffviewer/artifacts/<task>/`. Runner workspace artifacts live at `workspaces/TASK-XXX/artifacts/`.

**Artifact consumption from runners:**
- Level 1: Infer artifacts from `write`/`edit`/`bash` tool calls in NDJSON stream
- Level 2: Consume explicit `commandr_emit_artifact` events from RPC host tools

Only promote a bus event when Commandr has a concrete SPEC event and conformance case for artifact references.

## omp Runner Visibility

omp is an L2 worker, not the UI or bus. DiffViewer should make omp runs observable through Commandr and sidecars.

Expected future flow:

```
Commandr task packet
  -> commandr-omp-runner claims task
  -> omp executes in worktree/session
  -> runner emits neutral Commandr progress (Level 1: inferred from NDJSON)
  -> runner emits explicit artifacts/approvals via RPC host tools (Level 2)
  -> DiffViewer watches bus events + sidecar snapshots
  -> cockpit renders logs, diffs, approvals, artifacts
```

**Level 1 (current):** `commandr-omp-runner` uses `--mode json`. DiffViewer watches `.agents/events.jsonl` for `task_progress`, `task_complete`, `task_failed`. Approvals are logged-only (can't block).

**Level 2 (future):** `commandr-omp-runner` uses `--mode rpc`. DiffViewer can:
- Render explicit `artifact_created` events from `commandr_emit_artifact`
- Show `approval_requested` events with `status: pending` (blocking)
- Link to workspace artifacts at `workspaces/TASK-XXX/artifacts/`

UI requirements for omp visibility:

- Runner badge: `claude-code`, `opencode`, `omp`, `shell`, etc.
- Live log panel per runner session.
- Diff cards remain source-agnostic through `.diffviewer/turns/` snapshots.
- Approval requests render as action proposals with risk level (low/medium/high).
- Artifact cards link to review/evidence packages.
- Failure state separates runner crash from task completed with failing acceptance criteria.
- **Policy violation log:** Show `approval_requested` events with `status: logged_only` for post-hoc review.

## LSP Evidence Panel

Language servers should be a baseline evidence source for code-changing tasks. DiffViewer should not start every LSP globally. It should display LSP output when a runner or project profile exposes it.

Policy:

- LSP lifecycle belongs to L1/L2 runner adapters, not DiffViewer's UI state.
- DiffViewer/Tauri may start project-scoped LSPs later, but only through an explicit runner/session action.
- Cache summaries locally if useful; do not write raw LSP state to Commandr `.agents/`.
- Pair LSP diagnostics with typecheck/test status; do not treat clean diagnostics as task success.

UI targets:

| UI element | Evidence |
|---|---|
| Diagnostics badge | clean / dirty / unavailable per runner session |
| Diff card symbol panel | exported symbols changed, definitions, references/callers |
| Review package | diagnostics summary before approval |
| Risk scoring | higher risk when exported symbol changed and references exist |

This makes the cockpit feel IDE-aware without making DiffViewer the owner of language-server lifecycle.

## Neovim Operator Bridge

For operators using Neovim as an IDE replacement, DiffViewer should interoperate instead of trying to replace it.

Ideas:

- Deep link from a diff card or review package to `nvim <file> +<line>` or an operator-configured command.
- Accept a selection payload from Neovim and turn it into a `task_annotation` or steer proposal.
- Watch Neovim/Mason diagnostics summaries as evidence, not lifecycle state.
- Import DAP reproduction notes or stack traces as review/evidence artifacts.
- Refresh DiffViewer review state when diffview/Neovim sees external agent edits.

Boundary: Neovim remains the human IDE lane. DiffViewer owns review packages, approvals, evidence browsing, and bus projection.

## Suggested Implementation Slices

### Slice 0: Stabilize Current Browser Cockpit

Keep this slice small and do it before Tauri work.

Acceptance criteria:

- Recent turn history can replay after browser refresh, not only over live SSE.
- Demo cards are explicitly marked as synthetic and cannot imply direct steering.
- OpenCode direct steering displays success/failure state from `/steer`.
- Sidecar session ids are preserved well enough to target real OpenCode sessions.

### Slice 1: Action Registry Design Doc

Create `docs/COCKPIT-ACTIONS.md` with the action table, schemas, risk levels, and mapping to existing Commandr commands/events.

Acceptance criteria:

- All actions list owner: DiffViewer-local, Commandr command, or future runner adapter.
- High-risk actions require approval.
- No action bypasses Commandr for lifecycle state.

### Slice 2: Local Action Dispatcher

Implement a small in-process dispatcher around existing handlers.

Acceptance criteria:

- Browser/Tauri calls and agent proposals use the same dispatcher.
- Invalid schema returns a structured error.
- Risk level is visible to UI before execution.

### Slice 3: Review Package Artifact

Generate a task-level review package from existing data: TurnSnapshots, bus events, approval state, council verdict, and git diff summary.

Acceptance criteria:

- Output is a stable JSON or Markdown artifact under `.diffviewer/artifacts/<task>/`.
- It can be regenerated without mutating bus state.
- UI can render it as a card.

### Slice 4: Runner Panel

Render runner sessions from Commandr progress events and local log streams.

Acceptance criteria:

- Supports current Claude/OpenCode sidecars.
- Has integration path for `commandr-omp-runner` (Level 1 complete, Level 2 schema designed).
- Distinguishes running, completed, failed, and waiting-for-approval.
- Shows policy violations (logged approvals) for post-hoc review.

### Slice 4.5: LSP Evidence Panel

Add an evidence panel fed by runner-provided LSP summaries or project-scoped LSP adapters.

Acceptance criteria:

- UI can show diagnostics clean/dirty/unavailable for a task.
- Changed exported symbols can show definition/reference context when available.
- Missing LSP does not block review; it shows `unavailable`.
- LSP state is cached locally or in artifacts, not written as Commandr lifecycle state.

### Slice 5: Tauri Shell

Move the cockpit to Tauri only after action registry and artifacts stabilize.

Acceptance criteria:

- Existing browser UI remains usable during migration.
- SQLite/cache is derived, not authoritative.
- Native notifications are driven by bus/action state.

## Non-Goals

- Replacing Commandr `.agents/` with a DiffViewer database.
- Creating another task queue.
- Storing runner-private transcripts on the bus.
- Letting visual artifacts become the source of truth.
- Building Tauri before the action registry is understood.
